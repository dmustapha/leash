The problem

A raw key has no cap, and no off-switch.

Companies run fleets of paying agents.

Each one holds a key and pays for APIs, compute, and services on its own.

A leaked key can drain everything.

There is no per-payment ceiling, no daily budget, no active-hours window — just spend.

Cutting off one agent means touching every service by hand.

Rotate keys, revoke tokens, redeploy — service by service, while it keeps spending.

What you control

Six levers over every agent.

Identity

Bind the agent's external ERC-8004 / EVM identity. on-chain-resolved

Co-owned account

A 2-of-2 Hedera account — the agent and LEASH must both approve. Neither spends alone.

Limits

A hard per-payment cap, plus optional rolling daily/weekly soft budgets and an active-hours window.

Funding

Privy is the independent funding rail. An over-fund is denied before it goes out.

The signature lever

Kill-switch

One on-chain write revokes the agent everywhere; the next payment fails closed. Fully reversible — reactivate anytime.

Audit

Every ALLOW / DENY decision is logged to Hedera Consensus Service. The console shows a live spend feed.

The honest model

Control and independence — not trustlessness.

LEASH is a corporate-card model for agents. We're precise about what the chain does and what the facilitator does.

Read exactly how the model works
  • The chain stores the policy and records the revocation. The facilitator LEASH runs enforces the limits you set on each payment.
  • Identity is on-chain-resolved, not verified. We resolve the agent's ERC-8004 / EVM identity from the chain.
  • Rolling caps are a soft budget. Daily and weekly budgets are advisory guardrails; the per-payment cap is hard.
  • Privy denies over-funding on an independent rail. Funding is separate from spending; an over-fund is refused before it goes out.
  • The account is co-owned — 2-of-2. The agent holds its own key; LEASH holds only its co-signer key plus the agent's public key. Neither can spend alone.
  • LEASH binds agents, it doesn't mint them. You govern agents you already run.
