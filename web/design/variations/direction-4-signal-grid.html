The problem

A raw key has no cap and no off-switch.

Companies now run fleets of autonomous agents that pay for things on their own. Every one of them is holding a key that can spend without limit — and if one leaks, there's no single lever to pull.

  • No capA raw agent key can drain an account. There's no per-payment ceiling, no daily budget, no off-hours guard.
  • No off-switchCutting a leaked agent today means touching every service it can reach, by hand, one at a time.
  • No proofWhen an agent pays, there's no shared record of what was allowed and what was blocked.
How it works

Bind → Declare → Enforce → Revoke.

01 / BIND

Bind

Connect an agent you already run to an on-chain-resolved identity and a co-owned account.

02 / DECLARE

Declare

Set a hard per-payment cap, a soft daily/weekly budget, an allowlist, and active hours.

03 / ENFORCE

Enforce

The facilitator LEASH runs enforces the limits you set. Gas-free. Every decision logged.

04 / REVOKE

Revoke

One on-chain write cuts an agent off everywhere. Its next payment fails closed.

The honest model

What's true — and what isn't.

Read the honest model →
It's a corporate-card model, not trustless.You keep control and independence — but this isn't trust-free. The facilitator LEASH runs enforces the limits you set.
The chain stores the policy and records the revocation.What's on-chain is the spend policy and the kill event — not the payment path enforcement.
Identity is on-chain-resolved, not verified.We resolve the agent's external ERC-8004 / EVM identity on-chain. We don't attest to who's behind it.
Rolling caps are a soft budget.Daily and weekly limits are best-effort rolling budgets, not exact on-chain ceilings.
Privy is the independent funding rail.Privy funds the account and denies an over-fund before it goes out. Privy does not co-sign payments.
LEASH binds agents — it doesn't mint them.You bring an agent you already run. LEASH binds it to identity, an account, and limits.
