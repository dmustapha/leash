The instrument train

Bind. Declare. Enforce. Revoke.

Four beats, laid out the way a control room reads them — the load-bearing one sized larger.

Beat 01 · Bind

Bind an agent that already exists

Take an external autonomous agent and tie it to three things: an ENS name that declares its spend policy, a 2-of-2 co-signed Hedera spending account, and Privy as the independent funding rail. Neither the agent nor LEASH can spend alone — the account needs both keys.

bind(agent) → { ens, 2of2, privy }
Beat 02 · Declare

Declare policy on the name

Write the spend policy — max-per-call, allow-list, soft budget — into a resolver record on the agent's ENS name. On-chain-resolved, human-readable, editable.

setRecord("leash.policy", {...})
Beat 03 · Enforce

Enforce before settlement

The forked Hedera x402 facilitator we run reads the ENS-declared policy before every gas-free settlement. Over the cap, off the allow-list, over the soft budget — it fails closed.

facilitator.check(policy) → allow | deny
Beat 04 · Revoke

Revoke everywhere with one write

Cut one resolver record and the policy the facilitator reads is gone. The agent's next payment fails closed everywhere — across every rail that resolves the name — without touching the agent, its keys, or its code.

clearRecord("leash.policy") → ∅ → next settle() fails closed
The honest version

What LEASH actually does — and doesn't.

Read this before you demo it. The model is a corporate card, not magic.

the model A corporate-card model, not trustless. The chain stores the policy and records the revocation; the facilitator we run enforces the org's ENS-declared policy.
identity Agent identity is on-chain-resolved via ERC-8004 — resolved from the record, not a claim we've asserted about the agent.
the caps Max-per-call, daily and weekly limits are a soft budget — rolling caps the facilitator applies, not a chain-level ceiling.
funding Privy is the independent second rail on the funding flow. It denies over-funding from its own side, so the guardrails don't all live in one place.
the account The Hedera spending account is 2-of-2 co-signed — the agent holds one key, LEASH holds the other. Neither spends alone.
the boundary LEASH binds an agent — it doesn't create one. You bring the external agent; LEASH gives it a leash you can cut.
