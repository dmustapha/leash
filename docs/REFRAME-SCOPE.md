## 0. Why (the product truth)

LEASH stops *minting* agents and becomes the **spend-control plane for agents that already exist**. An agent's real self — logic, LLM, key, identity — lives **outside** LEASH (an EVM address / ERC-8004 registration it controls). LEASH binds that external identity to: an **ENS name (the leash)** + a **2-of-2 co-signed Hedera spending account** (agent holds one key, LEASH the other) + a **policy** (per-call cap, allowlist, rolling daily/weekly caps, time-windows) + **funding** (Privy) + **one-write revoke**. The create-your-own-agent product (provision + strategy + LLM + direction) is the **roadmap ("coming soon")**.

**Honest framing (locked — the two properties are DISTINCT):**
- **Control (TRUE):** LEASH co-controls the agent's spending account. The agent can't spend without LEASH's policy-checked co-signature; LEASH can't touch the agent's funds without the agent. Caps + revoke are real.
- **Independence (TRUE):** the agent holds its own key on the account (genuine co-owner) and its identity/logic/LLM are external and self-owned.
- **Trustlessness (FALSE — never claim):** the cap is enforced by LEASH's *decision to co-sign*, not by the chain. Same honest facilitator-trust boundary as today (INVARIANT #4). The chain enforces "two keys signed," NOT "why."

## 1. Decisions (USER, 2026-09-12)

- **Scope = ALL** (high builder throughput; parallel subagent dispatch): external-identity binding + **2-of-2 co-signed spending account** + register-existing flow + full dynamic limits (rolling daily/weekly + stateless time-windows) + on-chain-resolved ERC-8004.
- **Spending model = 2-of-2 co-signed Hedera account.** `KeyList[agentPub, leashCoSignerPub]`, `threshold=2`. Agent proposes + signs (1-of-2); LEASH co-signs at settle **only if `authorize()` returns `{settle:true}`**. `LEASH_COSIGNER_KEY` is DISTINCT from `HEDERA_OPERATOR_KEY` (fee-payer) — asserted at process start (throw if equal) so "LEASH's authority key ≠ its gas key" is literally true within the process. (Separate-trust-domain cosigner service = roadmap; disclosed in LIMITATIONS.)
- **AGENT-KEY OWNERSHIP (the linchpin of the whole model — SR-1).** The AGENT generates its own Hedera keypair and supplies ONLY its PUBLIC key (`agentPub`) at register. The agent's Hedera **private** key is held by the AGENT and is NEVER in LEASH's facilitator, DB, or env. This Hedera spending key is DISTINCT from the agent's external identity key (ERC-8004/EVM). Because LEASH holds only the cosigner key + the agent's pubkey, LEASH cannot move the agent's funds alone — F-031 depends ENTIRELY on this. If LEASH ever holds `agentPriv`, the 2-of-2 is theater and the co-ownership claim is false. No proof-of-control needed on `agentPub` (a wrong pubkey is self-defeating — the holder simply can't produce the 1-of-2 sig). The x402 client runs AGENT-SIDE and signs with `agentPriv` (the demo/VM-3 agent is an external process holding its own key — SR-2), NOT a LEASH-held key.
- **Identity = external, on-chain-resolved, advisory.** Register accepts an EVM address and/or an ERC-8004 `agentId`; LEASH calls the canonical ERC-8004 Identity Registry on Ethereum Sepolia (`0x8004A818BFB912233c491871b3d84c89A494BD9e`, ABI verified against the live contract at build) to **resolve** the owner, and writes ENS text records (`agent.erc8004` CAIP + `agent.address`). Labeled **"on-chain-resolved"**, NOT "verified" (ownerOf does not prove the registrant controls the address; proof-of-control = roadmap). Stays ADVISORY (INVARIANT #13); enforcement reads only `leash.policy`.
- **Dynamic limits = rolling + windows.** `leash.policy` gains `dailyCap`, `weeklyCap`, `allowedWindows`. Rolling totals read from the **HCS topic via the Hedera Mirror Node** (a chain-artifact read, but a LAGGING index — a **soft budget**, not a settle-live hard cap). Window check is stateless (pure gate).
- **ADDITIVE, network-typed.** Co-sign + dynamic limits apply to NEW `/app` register-existing agents. `/demo` sandbox + its single-key account + VM-1/VM-2 stay FROZEN. The facilitator registers TWO schemes (or one that BRANCHES on whether `policy.hederaAccount` is a KeyList account): single-key path (UNCHANGED — the VM floor) vs co-sign path.
- **PROTO-GATE after Group S** (safety net): a live 2-beat proto-VM3 proves the co-sign works before R/D are built; if it fails live, FALL BACK to the single-key governed-account model (identity binding + dynamic limits still ship, VM-1/VM-2 stay green).
- **Roadmap (park):** create-your-own-agent + strategy/LLM, Privy-intents human approval, ERC-8004 signed proof-of-control, separate-trust-domain cosigner service.

## 6. Adversarial review outcomes (BINDING refinements, 2026-09-12)
Three reviewers (architect / security-auditor / code-reviewer) audited this scope + the canonical docs pre-code. BLOCKER/MAJOR findings, now binding:
- **REF-1 (BLOCKER, co-sign seam):** don't mutate the single shared `hederaScheme()`; register a **network/account-typed scheme selection** (single-key path untouched for /demo). Custom `verifyPayerSignature` (accept agent 1-of-2 at verify) + custom dual-sign `signAndSubmit`. Verify at build that `@x402/hedera@2.25` permits a custom `signAndSubmit` adding a non-fee-payer sig (confirmed feasible by spike; S-GATE re-proves live). → S2.
- **REF-2 (BLOCKER, account model):** a KeyList account has no key-derived EVM alias — it breaks the canonical funding==payer==binding identity (DEV-020). NET-NEW provisioning; fund via the account's **long-zero EVM address**; retarget `reconcileFundingAllowlist` to it; replace `isCanonical`'s alias assertion with a KeyList-shape assertion; `provision-canonical.ts`/`ensureCanonicalAgent` NO-TOUCH. Verify long-zero HTS funding live (S-GATE). If it fails, the Privy DENY beat is demoed on the treasury source (still qualifies). → S1/R2.
- **REF-3 (BLOCKER, honesty):** the 2-of-2 is facilitator-trusted, NOT trustless. Reword all copy: control = TRUE (co-sign veto), trustless = FALSE. Assert `LEASH_COSIGNER_KEY ≠ HEDERA_OPERATOR_KEY` at startup. MUST-NOT-CLAIM: "chain enforces the cap" / "LEASH can't move a co-signed agent's funds once the agent's partial sig is presented." → §0/§1, INVARIANTS, MUST-NOT-CLAIM.
- **REF-4 (BLOCKER, rolling fail-open):** spend-rollup NEVER catches to a default-0 (mirror-down would silently un-cap); throw ⇒ `RPC_ERROR` DENY. Malformed cap ⇒ `MALFORMED_POLICY`. Overspend worst case ≈ **C × maxPerCall** under C concurrency (disclose; serialize per-agent settle if the tighter bound is wanted) — NOT 1×. Rolling cap = SOFT budget. → D3, INVARIANTS #3, LIMITATIONS.
- **REF-5 (MAJOR, identity honesty):** "verified" ⇒ **"on-chain-resolved"** (no proof-of-control). Owner-mismatch path required. Pin the REAL ERC-8004 ABI. → R1/R3, LIMITATIONS, CLAIMS.
- **REF-6 (MAJOR, #13 drift):** CI module-boundary guard — facilitator enforcement reads EXACTLY `leash.policy`; any `agent.*` read in `facilitator/` fails CI. → #13.
- **REF-7 (MAJOR, register atomicity):** pin write order — `leash.policy` LAST ⇒ partial register inert; funding UNION behind `requireOwner`. → R2.
